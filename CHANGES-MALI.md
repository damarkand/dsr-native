# Изменения для Mali (ветка `mali`, от v0.3.0)

Цель: Redmi Note 10S (Helio G95, Mali-G76 MC4, Vulkan 1.1, нет BC, нет dynamic rendering, 2 быстрых ядра).
Всё новое поведение — за ключами `settings.txt`, по умолчанию выключено; пути Adreno не изменены.
Замеры: второй запуск в той же локации (кеши пайплайнов и ETC2 прогреты) против базы.

## Этап 1

### Звук: переоткрытие потока AAudio после отключения (исправление ошибки, без ключа)

`src/hle/audio.cpp`, коммит `167da42`. После `AAUDIO_ERROR_DISCONNECTED` (наушники, Bluetooth, перезапуск
аудиосервера) каждая запись падала мгновенно: 227 тыс. строк лога за ~14 с, буферы отдавались игре без паузы,
поток FMOD mixer ел 6.6 с CPU за 10 с, звука не было до перезапуска. Теперь поток закрывается и открывается заново
(не чаще раза в 1 с, интервал удваивается до 32 с, пока не получается); без потока сэмплы «проигрываются» в реальном
времени. При `audio_smooth = 1` pacer читает поток под своей блокировкой и считает позицию нового потока от уже
записанного (счётчик нового потока начинается с 0, иначе выдача буферов встала бы).

Лог: один `AAudio stream disconnected: reopening`, затем `AAudio stream: ... Hz ...`; строка `audio out` раз в
~10 с заканчивается на `stream reopened Nx`.

### Время GPU на Mali

`GPU busy` на G76 всегда 0 мс, поэтому `fps = auto` видел только CPU. Бэкенд меряет каждую отправку
timestamp'ами GPU, только если драйвер сообщает `timestampComputeAndGraphics = 1`.

Всегда (только диагностика, поведение не меняется):
- при старте: `GPU timestamps: timestampComputeAndGraphics N, queue valid bits N, period N ns: used / not used`;
- один раз: `GPU timestamps unusable: start N, end N`, если драйвер пишет равные или нулевые значения;
- раз в 10 с, только если есть сбои: `GPU timestamps in the last 10 s: N used, N not available, N unusable`.

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `gpu_timestamps` | 0 | 1: timestamp'ы на каждую отправку, даже если `timestampComputeAndGraphics = 0` (при valid bits > 0) |
| `gpu_time_fences` | 0 | 1: поток `dsr-gputime` засекает, когда завершается каждая отправка (пустой submit со своим фенсом); строка `GPU busy (fences) N ms in the last 10 s (N ms per frame, ...; present N ms per frame)`; сумма за кадр идёт в `fps = auto` |

Оговорка по `gpu_time_fences`: если GPU простаивал к моменту отправки, задержка ядра и пробуждения потока
(~0.1–0.5 мс) считается занятостью; при ~20 отправках на кадр оценка завышена на несколько мс на кадр. Цена: один
пустой `vkQueueSubmit` на отправку в потоке recorder.

| Замер | База | Результат |
|---|---|---|
| `GPU busy` | 0 мс | _ждёт теста_ |
